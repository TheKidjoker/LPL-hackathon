# Seed Data

Everything in `data/` is generated by `scripts/make_seed_data.py` (owner: Kaylin; contact history and pre-seeded cases added by Thomas). All names, numbers, and companies are fake. The output is the same every run (fixed random seed).

```powershell
python scripts/make_seed_data.py      # regenerate data/
python scripts/seed_dynamodb.py       # load it into the live tables (or press Reset demo in the app)
```

| File | What |
|---|---|
| `accounts.json` | 10 Accounts, each with a `contactLog` and `advisorNotes` |
| `transactions.json` | 90 days of normal history for every account, ending Oct 1, 2026 (145 rows) |
| `scenarios.json` | The `POST /withdrawals` request for each of the 6 demo scenarios, with the expected result |
| `cases.json` | 4 pre-seeded Cases, one in each state |
| `audit.json` | The audit rows for those Cases (17 rows) |

`data/` ships to Lambda as a layer (`/opt`), so **Reset demo** (`POST /demo/reset`) deletes every case and audit row and reloads all of it in a few seconds. The frontend imports the same files for mock mode.

## Contact log and advisor notes

Every account carries what the firm already knew before the withdrawal. Juno reads both when scoring, the staff views show them, and the client's "Is this a scam?" checks are added to the contact log live.

```json
"contactLog": [
  {
    "at": "2026-10-01T14:02:00Z",
    "channel": "phone",
    "party": "client",
    "who": "Margaret Ellis",
    "summary": "Asked to raise her online daily transfer limit. Said \"the bank security department\" is helping her protect her money. Rep suggested calling her advisor; she declined."
  }
],
"advisorNotes": [
  { "at": "2026-08-14T15:00:00Z", "by": "Daniel Reyes", "text": "Annual review. Margaret was widowed in March; her daughter Susan helps with bills. Conservative, income-focused. Has never shown interest in crypto." }
]
```

| Field | Values |
|---|---|
| `channel` | `phone`, `email`, `branch`, `web_chat`, `web`, or `juno` (a client's "Is this a scam?" check) |
| `party` | `client`, `third_party` (someone else calling about the client, highlighted as "Someone else"), or `advisor` |
| `verdict` | Only on `juno` entries: `likely_scam`, `suspicious`, `looks_safe`, `need_more` |
| `id` | Only on `juno` entries: the check's ID, so one conversation stays one entry |

What the history adds to each story:

| Client | What the firm already knew |
|---|---|
| Margaret | Asked how fast a wire can go to "a crypto account", then to raise her transfer limit with "bank security" helping |
| David | Advisor documented the house purchase and called the title company to verify the wire instructions. His score dropped from 22 to 15 once Juno could see this |
| Harold | Nephew Kevin asked for statements to go to his email, and about same-day withdrawals for "an investment opportunity" |
| Dorothy | Asked about Bitcoin for a "friend stuck in customs"; a rep warned her about romance scams. Juno's memo cites the ignored warning |
| Eleanor | Asked to withdraw cash for gift cards "for my grandson's bail" |
| Robert | Showed the RV purchase agreement at the branch |
| Janet | Emailed asking how to wire an upfront fee to a "recovery" firm promising to return $40,000 she lost in a crypto scam, then called saying the fee was due "by Friday" |
| Walter | A caller claiming to be Microsoft asked for his account number "to process a refund" |

## Adding a scenario

1. Add the account to `ACCOUNTS` (or `PRESEED_ACCOUNTS` for a pre-seeded case), its history rules, and its `CONTACT_LOG` and `ADVISOR_NOTES` entries in `scripts/make_seed_data.py`.
2. Add the request to `SCENARIOS` with `expectedLevel`.
3. Run `python scripts/make_seed_data.py`, then `python -m pytest` (some tests count accounts) and `python ai/eval/run_eval.py` to score it live.
4. Redeploy the backend so the data layer updates, then press **Reset demo**.
